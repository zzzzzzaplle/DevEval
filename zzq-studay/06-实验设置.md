# 实验设置

## 三种实验设置

DevEval 提供了三种不同的实验设置，用于评估模型在不同上下文场景下的代码生成能力。

### 1. Without Context (无上下文)

#### 定义

**不提供任何项目上下文**，仅基于函数签名和需求描述生成代码。

#### 适用场景

- 评估模型的基础代码生成能力
- 不依赖项目特定知识的场景
- 快速评估和对比模型

#### 提示词结构

```
Functionality: {requirement.Functionality}

Arguments: {requirement.Arguments}

{signature}
```

#### 示例

```python
# 输入
Functionality: Check if the input value is JSON serializable. It checks if the input value is of the JSON serializable types.

Arguments: 
:param val: Any. The input value to be checked for JSON serializability.
:return: Bool. True if the input value is JSON serializable, False otherwise.

def is_json_serializable(val):

# 期望输出
    if isinstance(val, (str, int, float, bool, type(None))):
        return True
    elif isinstance(val, (list, tuple)):
        return all(is_json_serializable(item) for item in val)
    elif isinstance(val, dict):
        return all(is_json_serializable(key) and is_json_serializable(value) 
                   for key, value in val.items())
    return False
```

#### 评估特点

- **难度**: 较高
- **依赖召回率**: 无法评估（无上下文）
- **功能正确性**: 主要评估指标

### 2. Local Completion (本地文件补全)

#### 定义

提供**本地文件的上下文代码**（函数签名之前的代码），模拟开发者在文件末尾添加新代码的场景。

#### 适用场景

- 模拟实际的代码编写场景
- 评估模型利用文件上下文的能力
- 测试代码风格一致性

#### 提示词结构

```
{contexts_above}

Functionality: {requirement.Functionality}

Arguments: {requirement.Arguments}

{signature}
```

#### 示例

```python
# 输入（包含文件上文）
import json
from typing import Any

def is_dict(obj):
    return isinstance(obj, dict)

def is_list(obj):
    return isinstance(obj, list)

# ... 其他代码 ...

Functionality: Check if the input value is JSON serializable...

Arguments: 
:param val: Any. The input value to be checked...

def is_json_serializable(val):

# 期望输出
    if isinstance(val, (str, int, float, bool, type(None))):
        return True
    elif is_list(val) or is_dict(val):  # 使用文件中已有的函数
        if is_list(val):
            return all(is_json_serializable(item) for item in val)
        else:
            return all(is_json_serializable(key) and is_json_serializable(value) 
                       for key, value in val.items())
    return False
```

#### 评估特点

- **难度**: 中等
- **依赖召回率**: 可评估文件内依赖
- **功能正确性**: 主要评估指标

### 3. Local Infilling (本地文件填充)

#### 定义

提供**本地文件的完整上下文**（函数签名之前和之后的代码），模拟开发者在文件中间插入代码的场景。

#### 适用场景

- 评估模型理解完整文件上下文的能力
- 测试代码插入的位置正确性
- 最接近实际开发场景

#### 提示词结构

```
{contexts_above}

Functionality: {requirement.Functionality}

Arguments: {requirement.Arguments}

{signature}

{contexts_below}
```

#### 示例

```python
# 输入（包含上文和下文）
import json
from typing import Any

def is_dict(obj):
    return isinstance(obj, dict)

def is_list(obj):
    return isinstance(obj, list)

# ... 其他代码 ...

Functionality: Check if the input value is JSON serializable...

Arguments: 
:param val: Any. The input value to be checked...

def is_json_serializable(val):

# 下文代码
def validate_json(data):
    if not is_json_serializable(data):
        raise ValueError("Data is not JSON serializable")
    return json.dumps(data)

def load_json_file(filepath):
    with open(filepath, 'r') as f:
        data = json.load(f)
    return data

# 期望输出
    if isinstance(val, (str, int, float, bool, type(None))):
        return True
    elif is_list(val):
        return all(is_json_serializable(item) for item in val)
    elif is_dict(val):
        return all(is_json_serializable(key) and is_json_serializable(value) 
                   for key, value in val.items())
    return False
```

#### 评估特点

- **难度**: 较低（上下文最丰富）
- **依赖召回率**: 可评估完整依赖
- **功能正确性**: 主要评估指标

## 提示词工程

### 提示词文件结构

```
Experiments/prompt/
├── LM_prompt_elements.jsonl              # 语言模型提示元素
├── without_context/
│   ├── gpt-35-1106_prompt.jsonl         # GPT-3.5 提示词
│   └── gpt-4-1106_prompt.jsonl          # GPT-4 提示词
├── local_completion/
│   └── ...
└── local_infilling/
    └── ...
```

### 提示词元素

#### LM_prompt_elements.jsonl

每个样本包含：

```json
{
  "namespace": "benedict.utils.type_util.is_json_serializable",
  "prompt": "完整提示词",
  "signature": "def is_json_serializable(val):",
  "requirement": {
    "Functionality": "...",
    "Arguments": "..."
  },
  "context_above": "上文代码（如果有）",
  "context_below": "下文代码（如果有）"
}
```

### 提示词设计原则

#### 1. 明确的功能描述

```
✅ 好的描述:
Check if the input value is JSON serializable. It checks if the input 
value is of the JSON serializable types.

❌ 差的描述:
Make a function for JSON.
```

#### 2. 清晰的参数说明

```
✅ 好的说明:
:param val: Any. The input value to be checked for JSON serializability.
:return: Bool. True if the input value is JSON serializable, False otherwise.

❌ 差的说明:
Input: val
Output: bool
```

#### 3. 合理的上下文长度

- **Without Context**: 0 tokens
- **Local Completion**: ~500-2000 tokens
- **Local Infilling**: ~1000-4000 tokens

## 模型解码策略

### 1. 贪婪解码 (Greedy Decoding)

#### 配置

```python
temperature = 0
top_p = 1
max_tokens = 512
```

#### 特点

- **确定性输出**: 相同输入总是产生相同输出
- **计算效率高**: 单次生成
- **适用场景**: Pass@1 评估

#### 使用场景

```bash
# 模型目录名后缀 _greedy
Experiments/without_context/gpt-4-1106-preview_greedy/
```

### 2. 采样解码 (Sampling)

#### 配置

```python
temperature = 0.8
top_p = 0.95
max_tokens = 512
n = 20  # 生成 20 个样本
```

#### 特点

- **多样性输出**: 产生不同的代码变体
- **计算开销大**: 多次生成
- **适用场景**: Pass@3,5,10 评估

#### 使用场景

```bash
# 模型目录名无后缀
Experiments/without_context/gpt-4-1106-preview/
```

## 实验配置建议

### 1. 基础评估

**推荐配置**:
- 设置: Without Context
- 解码: Greedy
- 指标: Pass@1

**用途**: 快速评估模型基础能力

### 2. 综合评估

**推荐配置**:
- 设置: 所有三种
- 解码: Greedy + Sampling
- 指标: Pass@1,3,5,10 + Recall@1,3

**用途**: 全面评估模型性能

### 3. 应用评估

**推荐配置**:
- 设置: Local Infilling
- 解码: Greedy
- 指标: Pass@1 + Recall@1

**用途**: 评估实际应用场景表现

## 提示词优化建议

### 1. 需求描述优化

- 使用清晰的功能描述
- 提供详细的参数说明
- 包含示例输入输出（如果适用）

### 2. 上下文选择

- 选择相关的上下文代码
- 控制上下文长度（< 4000 tokens）
- 避免无关代码干扰

### 3. 格式一致性

- 统一缩进风格
- 保持命名约定一致
- 遵循项目代码规范

## 实验注意事项

### 1. 公平对比

- 使用相同的解码参数
- 使用相同的提示词模板
- 确保测试环境一致

### 2. 结果可复现

- 固定随机种子
- 记录所有参数
- 保存完整的实验日志

### 3. 多次实验

- 运行多次采样实验
- 计算平均值和标准差
- 报告统计显著性

## 实验结果分析

### 1. Pass@k 增长曲线

观察不同 k 值的 Pass@k 增长：
- 快速增长: 模型稳定性好
- 缓慢增长: 模型多样性低

### 2. 设置间的性能差异

分析不同设置的性能差距：
- 差距大: 模型依赖上下文
- 差距小: 模型独立性强

### 3. 主题分析

按编程主题分析性能：
- 识别强项和弱项
- 分析原因
- 指导改进方向
