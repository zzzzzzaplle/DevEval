# 数据格式详解

## 元数据文件 (data.jsonl)

### 基本信息

- **文件名**: `data.jsonl`
- **格式**: JSON Lines (每行一个 JSON 对象)
- **总样本数**: 1,825 个
- **来源**: 压缩包 `data.tar.gz`

### 数据结构

每个样本包含以下字段：

#### 1. namespace (命名空间)
```json
"namespace": "benedict.utils.type_util.is_json_serializable"
```
- **类型**: string
- **说明**: 代码的唯一标识符
- **格式**: `{package}.{module}.{function_name}`
- **用途**: 样本的唯一标识

#### 2. type (类型)
```json
"type": "function"
```
- **类型**: string
- **取值**:
  - `function`: 独立函数
  - `method`: 类的成员方法
- **说明**: 标识代码的类型

#### 3. project_path (项目路径)
```json
"project_path": "Text-Processing/python-benedict"
```
- **类型**: string
- **格式**: `{主题类别}/{项目名称}`
- **说明**: 项目在 Source_Code 目录中的相对路径

#### 4. completion_path (补全文件路径)
```json
"completion_path": "Text-Processing/python-benedict/benedict/utils/type_util.py"
```
- **类型**: string
- **说明**: 需要补全代码的文件路径
- **用途**: 定位目标文件

#### 5. signature_position (签名位置)
```json
"signature_position": [53, 53]
```
- **类型**: list[int, int]
- **格式**: [起始行号, 结束行号]
- **说明**: 函数/方法签名在文件中的行号范围
- **注意**: 行号从 1 开始计数

#### 6. body_position (函数体位置)
```json
"body_position": [54, 55]
```
- **类型**: list[int, int]
- **格式**: [起始行号, 结束行号]
- **说明**: 函数体在文件中的行号范围
- **用途**: 指定需要生成的代码位置

#### 7. dependency (依赖关系)
```json
"dependency": {
  "intra_class": [],
  "intra_file": [],
  "cross_file": []
}
```
- **类型**: dict
- **子字段**:
  - `intra_class`: list[string] - 类内依赖
  - `intra_file`: list[string] - 文件内依赖
  - `cross_file`: list[string] - 跨文件依赖
- **说明**: 代码依赖的其他函数/方法

**依赖类型详解**:

| 依赖类型 | 定义 | 示例 |
|---------|------|------|
| intra_class | 同一个类内的其他方法 | 类A的方法B调用类A的方法C |
| intra_file | 同一个文件内的其他函数 | 文件X的函数A调用文件X的函数B |
| cross_file | 其他文件中的函数 | 文件X的函数A调用文件Y的函数B |

#### 8. requirement (需求说明)
```json
"requirement": {
  "Functionality": "Check if the input value is JSON serializable...",
  "Arguments": ":param val: Any. The input value to be checked..."
}
```
- **类型**: dict
- **子字段**:
  - `Functionality`: string - 功能描述
  - `Arguments`: string - 参数和返回值说明
- **用途**: 提供给模型的代码生成需求

#### 9. tests (测试用例)
```json
"tests": ["tests/utils/test_type_util.py::type_util_test_case::test_is_json_serializable"]
```
- **类型**: list[string]
- **格式**: pytest 格式的测试路径
- **说明**: 用于验证生成代码的测试用例

#### 10. indent (缩进)
```json
"indent": 4
```
- **类型**: int
- **说明**: 代码的缩进空格数
- **用途**: 确保生成代码的格式正确

## 完整示例

```json
{
  "namespace": "benedict.utils.type_util.is_json_serializable",
  "type": "function",
  "project_path": "Text-Processing/python-benedict",
  "completion_path": "Text-Processing/python-benedict/benedict/utils/type_util.py",
  "signature_position": [53, 53],
  "body_position": [54, 55],
  "dependency": {
    "intra_class": [],
    "intra_file": [],
    "cross_file": []
  },
  "requirement": {
    "Functionality": "Check if the input value is JSON serializable. It checks if the input value is of the JSON serializable types.",
    "Arguments": ":param val: Any. The input value to be checked for JSON serializability.\n:return: Bool. True if the input value is JSON serializable, False otherwise."
  },
  "tests": ["tests/utils/test_type_util.py::type_util_test_case::test_is_json_serializable"],
  "indent": 4
}
```

## 生成代码格式 (completion.jsonl)

### 格式要求

模型生成的代码需要保存为 JSONL 格式：

```json
{
  "namespace": "benedict.utils.type_util.is_json_serializable",
  "completion": "    config_options = {}\n    # Code to retrieve options...\n    return config_options\n"
}
```

### 字段说明

#### namespace
- 与元数据中的 namespace 对应
- 用于匹配测试样本

#### completion
- **类型**: string
- **格式**: 函数体的代码内容
- **要求**:
  - 保持正确的缩进
  - 不包含函数签名
  - 可以包含注释和空行

## 依赖数据格式

### Dependency_Data 目录

```
Dependency_Data/
├── Text-Processing/
│   ├── python-benedict/
│   │   └── analyzer_result.pkl
│   └── ...
└── ...
```

### 数据内容

- **格式**: pickle 文件
- **内容**: 预计算的依赖分析结果
- **用途**: 加速 Recall@k 评估

## 评估结果格式

### test_output.jsonl

```json
{
  "namespace": "benedict.utils.type_util.is_json_serializable",
  "completion": "...",
  "Result": "Pass"
}
```

**Result 取值**:
- `Pass`: 所有测试通过
- `Error`: 测试失败或执行错误
- `TimeOut`: 执行超时 (60秒)
- `OOM`: 内存溢出 (>5GB)

### dependency_results.jsonl

```json
{
  "namespace": "benedict.utils.type_util.is_json_serializable",
  "completion": "...",
  "generated_dependency": {
    "intra_class": ["method1", "method2"],
    "intra_file": ["func1"],
    "cross_file": ["module.func"]
  }
}
```
