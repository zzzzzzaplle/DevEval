# 使用指南

## 环境搭建

### 1. 安装 Conda 环境

```bash
# 创建虚拟环境
conda create --name DevEval --file environment.txt

# 激活环境
conda activate DevEval
```

### 2. 安装 Python 依赖

```bash
# 安装 Python 包
pip install -r requirement.txt

# 设置 NLTK 数据路径
echo "export NLTK_DATA=/home/user/DevEval/nltk_data" >> ~/.bashrc
source ~/.bashrc
```

### 3. 下载必要数据

#### 源代码仓库
```bash
# 从 HuggingFace 下载
wget https://huggingface.co/datasets/LJ0815/DevEval/blob/main/Source_Code.tar.gz

# 解压到根目录
tar -xzvf Source_Code.tar.gz

# 确保目录结构为: DevEval/Source_Code/
```

#### 依赖数据
```bash
# 从 HuggingFace 下载
wget https://huggingface.co/datasets/LJ0815/DevEval/blob/main/Dependency_Data.tar.gz

# 解压到根目录
tar -xzvf Dependency_Data.tar.gz

# 确保目录结构为: DevEval/Dependency_Data/
```

#### 元数据
```bash
# 解压元数据
tar -xzvf data.tar.gz

# 生成 data.jsonl
```

### 4. 验证环境

```bash
# 运行基准测试，验证环境是否正常
python pass_k.py

# 成功后会在当前目录生成 failed_samples.jsonl
```

## 运行评估

### Pass@k 评估

#### 基本用法

```bash
# 使用提供的脚本
bash run_pass_k.sh
```

#### 手动运行

```bash
# 检查源代码完整性
python check_source_code.py ./Source_Code

# 计算 Pass@1 (贪婪解码)
python pass_k.py \
    --output_file ./Experiments/without_context/gpt-4-1106-preview_greedy/completion.jsonl \
    --log_file ./Experiments/without_context/gpt-4-1106-preview_greedy/test_output.jsonl \
    --source_code_root ./Source_Code \
    --data_file ./data.jsonl \
    --n 1 \
    --k 1

# 计算 Pass@3,5,10 (采样解码)
python pass_k.py \
    --output_file ./Experiments/without_context/gpt-4-1106-preview/completion.jsonl \
    --log_file ./Experiments/without_context/gpt-4-1106-preview/test_output.jsonl \
    --source_code_root ./Source_Code \
    --data_file ./data.jsonl \
    --n 20 \
    --k 3,5,10
```

#### 参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| `--output_file` | 模型生成的代码文件 | completion.jsonl |
| `--log_file` | 评估结果输出文件 | test_output.jsonl |
| `--source_code_root` | 源代码仓库根目录 | ./Source_Code |
| `--data_file` | 元数据文件 | ./data.jsonl |
| `--n` | 每个任务生成的代码数量 | 1, 20 |
| `--k` | Pass@k 的 k 值 | 1, 3,5,10 |

### Recall@k 评估

#### 基本用法


#### 参数说明

| 参数 | 说明 | 示例 |

## 准备模型输出

### 格式要求

将模型的预测结果保存为 JSONL 格式：

```json
{
  "namespace": "benedict.utils.type_util.is_json_serializable",
  "completion": "    for item in val:\n        if not is_json_serializable(item):\n            return False\n    return True\n"
}
```

### 文件命名和位置

```
Experiments/
└── {实验设置}/
    └── {模型名称}_{解码方式}/
        └── completion.jsonl
```

**示例**:
- `Experiments/without_context/gpt-4-1106-preview_greedy/completion.jsonl`
- `Experiments/local_completion/codellama-7b/completion.jsonl`

## 实验设置

### 1. Without Context (无上下文)

**说明**: 仅基于函数签名和需求描述生成代码

**提示词结构**:
```
{requirement.Functionality}
{requirement.Arguments}

{signature}
```

**适用场景**: 评估模型的基础代码生成能力

### 2. Local Completion (本地文件补全)

**说明**: 基于函数签名、需求描述和本地文件上文生成代码

**提示词结构**:
```
{文件上文代码}

{requirement.Functionality}
{requirement.Arguments}

{signature}
```

**适用场景**: 模拟开发者在文件末尾添加新代码

### 3. Local Infilling (本地文件填充)

**说明**: 基于函数签名、需求描述和本地文件上下文（上文+下文）生成代码

**提示词结构**:
```
{文件上文代码}

{requirement.Functionality}
{requirement.Arguments}

{signature}

{文件下文代码}
```

**适用场景**: 模拟开发者在文件中间插入代码

每个提示词元素包含：

- `signature`: 函数签名
- `requirement`: 需求描述
- `context`: 上下文代码（如果有）

## 评估流程详解

### Pass@k 评估流程

1. **加载元数据**: 读取 `data.jsonl`
2. **加载模型输出**: 读取 `completion.jsonl`
3. **代码替换**: 
   - 定位目标文件
   - 备份原文件
   - 用生成代码替换函数体
4. **执行测试**:
   - 运行 pytest 测试
   - 监控内存使用
   - 设置超时限制
5. **恢复文件**: 恢复原始代码
6. **统计结果**: 计算 Pass@k

### Recall@k 评估流程

1. **加载元数据和模型输出**
2. **代码替换**: 同 Pass@k
3. **依赖分析**:
   - 解析生成代码
   - 提取函数调用
   - 识别依赖关系
4. **计算召回率**: 与真实依赖对比
5. **恢复文件**: 恢复原始代码

## 注意事项

### 评估安全

1. **并发限制**: 不要同时在同一仓库运行多个评估
   - 原因: 会互相修改文件
   - 建议: 串行评估或使用不同仓库副本

2. **内存控制**: 每个测试限制 5GB 内存
   - 超出会终止进程
   - 标记为 OOM

3. **超时设置**: 每个测试 60 秒超时
   - 防止无限循环
   - 标记为 TimeOut

### 数据完整性

1. **检查临时文件**: 
   ```bash
   python check_source_code.py ./Source_Code
   ```
   - 清理上次评估残留的临时文件

2. **不要修改仓库结构**: 
   - 保持原有的目录结构
   - 不要重命名或移动文件

### 结果解读

1. **Pass@k 值越高越好**
   - 代表功能正确性高
   
2. **Recall@k 值越高越好**
   - 代表依赖识别准确

3. **综合评估**: 结合两个指标全面评估模型能力

## 常见问题

### Q1: 如何添加新的模型评估？

**A**: 
1. 生成 `completion.jsonl` 文件
2. 放到 `Experiments/{设置}/{模型名}/` 目录
3. 运行评估脚本

### Q2: 评估中断了怎么办？

**A**: 
1. 运行 `check_source_code.py` 清理临时文件
2. 评估脚本会自动跳过已完成的样本
3. 从中断处继续评估

### Q3: 如何查看失败的样本？

**A**: 
- Pass@k: 查看 `{log_file}` 中 Result 不为 Pass 的样本
- Recall@k: 查看 `{log_file}` 中 generated_dependency 为 None 的样本

### Q4: 测试环境要求？

**A**:
- Python 3.9.18
- Linux 系统（推荐）
- 足够的磁盘空间（源代码约 2GB+）
- 足够的内存（建议 16GB+）
